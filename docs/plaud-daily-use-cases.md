# Plaud NotePin S 普段使い活用案 — AI人脈・パーソナルアシスタント構想

介護相談パイプライン(plaud-notepin-integration.md)とは別に、**日常業務・個人利用**での活用を検討する。
既存の技術資産(FastAPI + Claude + LINE Messaging API)はそのまま流用できる。

---

## 1. 本命: 「AI人脈」— 名刺交換・商談の会話を人物データベース化

### コンセプト

名刺交換や商談・会食のあと、NotePin にひとこと吹き込む(または会話そのものを録音)だけで、
**「誰と・いつ・何を話し・何を約束したか」が人物単位で蓄積され、LINE からいつでも引き出せる**状態を作る。

Plaud 純正の「AIに質問」は録音ファイル単位でしか聞けないが、自作連携なら
**「人」を軸に複数回の接触履歴を統合**でき、しかも使い慣れた LINE から一瞬で引き出せるのが差別化ポイント。

### 全体像

```
名刺交換・商談後に NotePin で録音(会話 or 直後の自分メモ)
        │ Plaud: 文字起こし・要約(話者識別)
        │ Zapier トリガー(要約完了)→ Webhook POST
        ▼
POST /plaud/contacts(FastAPI に新設)
        │ Claude で構造化抽出(JSON)
        │   氏名 / 会社・役職 / 出会った場所・経緯
        │   話した話題 / 相手の関心事・課題
        │   約束したこと(宿題)/ 次アクション / 人柄メモ
        ▼
人脈DB に保存(Notion DB / Google スプレッドシート / Postgres)
        ▼
LINE から活用(検索・ブリーフ・リマインド)
```

### LINE からの活用イメージ

| 操作 | ボットの応答 |
|------|-------------|
| 「山田さんって誰だっけ」 | 会社・役職・出会った経緯・前回話した内容・約束事項をカードで返す |
| 「明日会う人の予習」 | カレンダー連携で明日の面会相手を特定し、過去の接触履歴からブリーフを生成 |
| 「〇〇に詳しい人いたっけ」 | 話題・関心事を横断検索して該当人物をリストアップ |
| (自動)交換から3日後 | 「山田さんへのお礼連絡はお済みですか?資料送付の約束もあります」と push |
| 「山田さんにお礼メール書いて」 | 会話内容を踏まえたお礼メールの草案を生成 |

### 保存先の選択肢

| 保存先 | 長所 | 短所 |
|--------|------|------|
| Notion DB | Zapier から直接も書ける・スマホで一覧性が高い・無料枠あり | API 連携が1つ増える |
| Google スプレッドシート | 手軽・共有しやすい | 構造化検索が弱い |
| Postgres / SQLite(アプリ内) | 検索・統合の自由度が最大 | ホスティングに DB 追加が必要 |

まずは **Notion DB** が推奨(スキーマ変更が容易で、ボットを介さず直接眺める運用にもすぐ移行できる)。

### 実装フェーズ

1. **Phase 1**: `/plaud/contacts` Webhook + Claude 構造化抽出 + Notion 保存(録音 → 自動で人脈カードが増える状態)
2. **Phase 2**: LINE からの検索コマンド(「人脈 山田」等のプレフィックス、または Claude に意図判定させる)
3. **Phase 3**: プロアクティブ機能(お礼リマインド push、カレンダー連携の面会前ブリーフ)

## 2. その他の普段使いユースケース

同じ「録音 → Plaud 要約 → Webhook → Claude 加工 → LINE」の型で横展開できる。

### 案1: 音声メモ → TODO・リマインダー

移動中・運転中に思いついたことを NotePin に吹き込む → Claude が TODO / アイデア / 買い物メモ等に自動分類して LINE に整理して返す。期限らしき発言(「金曜までに」)があればリマインド日時も抽出。

### 案2: 打合せ後のフォローアップ自動化

商談・打合せの録音から「議事メモ + 自分の宿題 + 相手の宿題 + お礼メール草案」をワンセットで生成し LINE に届ける。会議が終わった瞬間にフォローアップの 8 割が済んでいる状態を作る。

### 案3: 日報・週報の自動下書き

1日の録音(メモ・打合せ)を夜にまとめて集約し、日報の下書きを生成。金曜には週次で「今週やったこと・来週やること」を自動整理。

### 案4: 家庭の記録(通院・学校面談・重要な電話)

病院での医師の説明、学校の三者面談などを録音 → 平易な要約と「確認すべきこと」を家族の LINE グループに共有。介護面談パイプライン(案A)の生活全般への一般化。

### 案5: アイデアジャーナル

思いつきを録りためておき、週1回 Claude が「今週のアイデア一覧 + 有望なものの深掘り提案」を配信。

## 3. 留意点

1. **録音のマナーと同意**: 自分が当事者の会話の録音は日本では直ちに違法ではないが、名刺交換・商談での無断録音は信頼を損なうリスクがある。**推奨運用は「会話そのもの」ではなく「別れた直後に自分の声で30秒メモを吹き込む」**方式。これなら同意問題がなく、Plaud の要約・構造化の恩恵はほぼ同等に受けられる。
2. **個人情報管理**: 人脈DBは氏名・所属を含む個人情報データベースになる。業務利用なら利用目的の範囲内で扱い、保存先(Notion 等)のアクセス権限を自分のみに限定すること。
3. **介護相談ボットとの分離**: 既存ボットは会社の福利厚生窓口という性格上、**個人用途は別の LINE 公式アカウント(またはチャネル)に分ける**こと。FastAPI アプリは同一コードベースに `/webhook`(介護相談)と `/personal/webhook`(個人アシスタント)を同居させれば運用コストは増えない。
4. **コスト**: Plaud 有料プラン + Zapier 有料枠 + Notion(無料枠で可)+ Claude API。月額を試算のうえ、まずは Zapier 無料枠(月100タスク)で PoC するのが現実的。

---

## 4. 結論

「名刺交換 → AI人脈」は普段使いとして最も効果が高く、既存資産の流用で実現可能。
**録音は会話本体ではなく直後のセルフメモ方式**にすれば、同意リスクなしで今日から運用を始められる。
推奨は Phase 1(録音 → 自動で Notion に人脈カード生成)からの段階導入。
