# Plaud NotePin S × 起業家メンタリング — 既存アプリ群の再検討

介護相談は担当外となったため、**ご自身が日々行う起業家メンタリング(KINCUBA)での活用**を軸に、
これまで Claude Code で作成した全アプリを棚卸しして Plaud NotePin S との連携を再検討する。

---

## 1. 既存アプリの棚卸しと Plaud 適合度

| アプリ | 概要 | Plaud 適合度 |
|--------|------|:---:|
| **KINCUBA Mentor Desk** | スタッフ向け個別相談支援。学生カルテ・面談準備・**面談記録(走り書きメモ→AI要約・次回アクション・フォローメール文案)**・事業診断OS | ◎ 本命 |
| **Startup Dojo Chat** | 学生向けAI壁打ち道場(8ステップ対話→診断→48時間アクション→メンター共有レポート) | ○ |
| kincuba-mind-shindan | 説明会向けミニ診断(キオスク) | △ イベント運営で補助的 |
| cybozu-scheduler-open | 複数社員の空き時間抽出・日程調整 | △ 次回面談調整で補助的 |
| ai-walluchi | 若手起業家向け壁打ちAI(Startup Dojo の前身的) | ○(Dojo と同様) |

**最大の発見: Mentor Desk の「面談記録」機能は、入力が「スタッフの走り書きメモ(`raw_memo`)」である点だけがボトルネック。**
メンタリング中にメモを取ると対話への集中が削がれ、メモを取らないと記録が痩せる。
NotePin はまさにこの入力部分を置き換えるデバイスであり、既存の AI 整理パイプライン(`/api/debrief`)はそのまま活きる。

## 2. 本命: メンタリング面談の「録音 → カルテ自動整理」

### 2-1. 今日からできる運用(開発ゼロ)

1. 面談冒頭に「記録のために録音しますね」と一言(メンタリングは同意を得やすい文脈)
2. NotePin で録音 → Plaud が文字起こし・要約(話者識別でメンター/学生を分離)
3. Plaud アプリから文字起こしをコピー → Mentor Desk **面談記録タブの「走り書きメモ」欄に貼り付け**
4. 既存の `/api/debrief` がそのまま「AI要約・学生の次回アクション・スタッフTODO・フォローメール文案」に整理

既存プロンプト(`lib/prompts.ts` の debrief)は「走り書きメモ」前提なので、
「文字起こし全文が貼られる場合もある」旨を1行追記すると精度が安定する(改修は実質それだけ)。

### 2-2. Phase 1: 録音インボックス + 手動紐づけ(推奨改修)

デイリーダッシュボード検討で採用した「**AIは下ごしらえ、振り分けは人間**」方式をそのまま適用する。

```
面談を NotePin で録音
    │ Plaud: 文字起こし・要約・話者識別
    │ Zapier トリガー(要約完了)→ Webhook POST
    ▼
Mentor Desk 新設 /api/plaud-inbox(サーバー側保存: Netlify Blobs or Supabase)
    ▼
学生一覧に「📥 未整理の録音 n件」バッジ
    ▼
スタッフが「これは〇〇さんの面談」と手動で紐づけ(1タップ)
    ▼
既存 debrief パイプラインが走り、面談記録としてカルテに保存
```

- Mentor Desk の保存層は現在 localStorage だが、`lib/store.ts` は「将来Supabaseに差し替える前提で全関数async・集約済み」と設計されているため、インボックス分だけサーバー保存を先行導入すればよい(mind-shindan で実績のある Netlify Blobs が最小コスト)
- 「どの学生の録音か」を AI に推定させてサジェスト表示しつつ、**確定はスタッフの1タップ**(誤紐づけ防止)

### 2-3. 話者識別で「メンタリングの質」も見える化(Phase 2)

Plaud の話者識別でメンター発言と学生発言を分離できるため、面談記録に以下を追加できる:

- **発話比率**: メンターが話しすぎていないか(理想は学生 7 : メンター 3 など)
- **学生の言語化度**: 学生が自分の言葉で事業を語れた箇所の引用
- **良い問いのログ**: 学生の思考が動いたメンターの質問を蓄積 → スタッフ育成・問いのナレッジ化

## 3. 事業診断OSとの連動

診断入力画面(13項目)には既に「壁打ちサマリーから自動プリフィル」の仕組みがある。
ここに**「面談の文字起こしからプリフィル」というソースを追加**すれば、
面談で学生が話した内容(顧客課題・解決策・収益仮説など)が診断項目に自動で入り、
**面談のたびに診断履歴が育つ**(前回比±点の成長記録機能がそのまま活きる)。

---

## 4. 学生側の活用(Startup Dojo Chat / ai-walluchi)

- **ピッチ練習の録音 → ピッチ診断**: 学生が実際に声に出したピッチを NotePin で録音し、文字起こしを Mentor Desk の「ピッチ診断」(不足スライド・想定質問・10分/3分/1分構成)にかける。書いた原稿ではなく**実際に話した内容**を診断できるのが価値
- **顧客インタビューの録音 → 顧客課題検証**: 学生が行った顧客インタビュー(相手の同意前提)の文字起こしを「顧客課題検証」(表面/本質の悩み・聞くべき10問)に投入。壁打ちの空論から実データの検証へ
- 学生に NotePin を貸し出す運用も考えられる(KINCUBA 備品として)

## 5. 補助的な活用

- **説明会・イベント(mind-shindan)**: 質疑応答を録音 → よくある質問と回答を FAQ 化し、次回イベントや Dojo Chat の案内文に反映
- **日程調整(cybozu-scheduler)**: 面談録から「次回は再来週あたりで」等の発言を拾い、スタッフTODOに「日程調整」を自動追加(スケジューラーで空き時間を提示)

## 6. 実装ロードマップ

| フェーズ | 内容 | 開発 |
|---------|------|------|
| Phase 0(今日から) | 録音 → Plaud 文字起こしコピー → 面談記録タブに貼り付け → 既存 debrief で整理 | ゼロ(プロンプト1行追記推奨) |
| Phase 1 | `/api/plaud-inbox` + Netlify Blobs + 「未整理の録音」バッジ + 手動紐づけ | 小〜中 |
| Phase 2 | 話者識別の質分析・診断入力プリフィル・フォローメールとの完全連結 | 中 |
| Phase 3 | 学生向け(ピッチ診断・顧客インタビュー検証)への展開 | 中 |

## 7. 運用ルール(必須)

1. **録音同意の定型化**: 面談冒頭の「記録と振り返りのために録音します。カルテ整理にAIを使います」を定型スクリプト化。拒否時は従来どおり手書きメモ
2. **学生の個人情報**: 録音・文字起こしは Plaud クラウドを経由する。KINCUBA(大学)側の個人情報・研究倫理ルールとの整合を事前確認
3. **カルテの保存先**: 本格運用時は localStorage から Supabase へ移行(store.ts は移行前提の設計済み)

---

## 8. 結論

**Plaud NotePin S の最有力用途は「Mentor Desk の面談記録の入力デバイス化」。**
既存の debrief パイプライン(要約・次回アクション・フォローメール自動生成)が「走り書きメモ」の代わりに
「面談まるごとの文字起こし」を受け取るだけで、開発ゼロ(Phase 0)から効果が出る。
メモを取らずに学生との対話へ完全集中でき、記録の質は逆に上がる — メンタリング業務との相性は
介護用途よりはるかに良い。まず Phase 0 を数回試し、手応えがあれば Phase 1(録音インボックス)の実装に進むことを推奨する。
